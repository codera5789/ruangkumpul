### Contoh alur pengguna membuat postingan

1. Pengguna login menggunakan Supabase Auth.
2. Next.js mendapatkan session pengguna melalui Supabase SSR.
3. Pengguna membuat postingan melalui form.
4. Zod memvalidasi input.
5. Server Action memverifikasi autentikasi dan otorisasi.
6. Supabase PostgreSQL menyimpan postingan.
7. RLS memastikan pengguna hanya dapat melakukan tindakan yang diizinkan.
8. Feed menampilkan postingan terbaru.
9. Sistem membuat notifikasi untuk anggota yang relevan.

### Batas keamanan

Jangan mengandalkan middleware untuk menjadi satu-satunya lapisan keamanan. Setiap operasi sensitif wajib memeriksa session dan authorization di server. Database RLS menjadi lapisan pertahanan tambahan.

Untuk MVP, semua akses database pengguna harus menggunakan pola yang mempertahankan identitas pengguna dan kebijakan RLS. Service role hanya untuk pekerjaan administratif terpercaya di server.

## 6.4. RLS policy wajib

| Tabel | Kebijakan |
|---|---|
| profiles | Publik hanya membaca informasi profil yang diizinkan; user mengubah profil sendiri |
| user_roles | Tidak ada self-assignment; admin berwenang mengelola |
| communities | Publik membaca komunitas public aktif |
| community_members | User mengelola keanggotaan sesuai aturan |
| posts | User mengelola konten miliknya; anggota sesuai visibility |
| comments | User mengelola komentar miliknya |
| reactions | User hanya dapat mengelola reaction miliknya |
| articles | Publik hanya membaca artikel published |
| tools | Publik membaca tools aktif |
| tool_favorites | User hanya mengakses favorit miliknya |
| bookmarks | User hanya mengakses bookmark miliknya |
| notifications | Hanya penerima yang boleh membaca dan mengubah status |
| reports | Pelapor dan moderator memiliki akses sesuai kebutuhan |
| audit_logs | Hanya admin berwenang |

**Catatan implementasi database:** gunakan migration SQL, trigger `updated_at`, unique constraint, index, dan helper authorization yang tidak menimbulkan recursive RLS. Untuk relasi polymorphic seperti `bookmarks` dan `reports`, buat validasi server-side dan pertimbangkan tabel relasi spesifik per domain bila integritas referensi menjadi kritis.
